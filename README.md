# Инструмент анализа графа зависимостей (Вариант №1, Этапы 1–3)

Дисциплина: **Конфигурационное управление**  
Группа: **ИКБО-51-25**  
Семестр: **3 семестр (осенний) 2026/2027**  
Вариант: **№1**  
Формат пакетов: **Python (pip)**  

---

## 1. Общее описание

Данный программный инструмент предназначен для сбора и анализа графа
зависимостей пакетов Python (pip) без использования сторонних библиотек
и готовых пакетных менеджеров.

Реализация охватывает **Этапы 1–3**:
1. **Этап 1. Минимальный прототип с конфигурацией**:
   - Чтение параметров из файла конфигурации JSON (`config.json`).
   - Полная валидация всех обязательных параметров и типов.
   - Вывод параметров в формате «ключ: значение».
   - Демонстрация обработки ошибок конфигурации.
2. **Этап 2. Сбор данных**:
   - Получение прямых runtime-зависимостей пакета заданной версии.
   - Разбор спецификаций зависимостей PEP 508 без использования `pip`.
   - Исключение опциональных зависимостей (`extra`).
   - Поддержка реального PyPI JSON API и локального тестового репозитория.
   - Вывод на экран списка прямых зависимостей.
3. **Этап 3. Основные операции над графом**:
   - Построение транзитивного графа зависимостей алгоритмом **DFS с рекурсией**.
   - Ограничение максимальной глубины обхода (`max_depth`).
   - Фильтрация пакетов по подстроке (`filter_substring`).
   - Корректная обработка циклических зависимостей с фиксацией циклов.
   - Поддержка режима тестирования с описанием графов заглавными латинскими
     буквами (`A`, `B`, `C`...).

## 2. Описание функций и настроек

### 2.1. Конфигурационные параметры (`config.json`)

| Параметр | Тип | Описание | Пример |
|---|---|---|---|
| `package_name` | `string` | Имя целевого пакета для анализа | `"requests"` / `"A"` |
| `repository_url` | `string` | URL PyPI или путь к файлу тестового репозитория | `"test_repos/simple_repo.json"` |
| `test_mode` | `boolean` | `true` — тестовый репозиторий, `false` — PyPI | `true` / `false` |
| `package_version` | `string` | Анализируемая версия пакета | `"2.31.0"` / `"1.0.0"` |
| `max_depth` | `integer` | Максимальная глубина обхода DFS (`>= 0`) | `3` |
| `filter_substring` | `string` | Подстрока для исключения пакетов | `""` или `"TEST"` |

### 2.2. Архитектура модулей

- `src.config`:
  - `load_config(filepath: str) -> AppConfig`: чтение и парсинг конфигурации.
  - `validate_config_dict(data: dict) -> AppConfig`: валидация ключей и типов.
- `src.collector`:
  - `parse_requirement_line(req_line: str) -> tuple[str, bool]`: синтаксический анализ строк зависимостей PEP 508.
  - `get_direct_dependencies(...) -> list[str]`: извлечение прямых зависимостей для заданной версии пакета.
  - `load_test_repository(repo_path: str) -> dict`: загрузка локальных графов тестового репозитория.
- `src.graph`:
  - `DependencyGraph`: структура данных графа (вершины, ориентированные ребра, списки смежности, циклы).
  - `build_dependency_graph(...) -> DependencyGraph`: построение графа зависимостей с помощью **рекурсивного DFS** с учетом `max_depth`, фильтрации и защиты от зацикливания.
- `src.main`:
  - CLI интерфейс с поддержкой выбора этапа (`--stage 1..3`).

## 3. Описание команд для сборки проекта и запуска тестов

### Сборка и окружение
Проект реализован на стандартной библиотеке Python 3.10+ и не требует внешних зависимостей.

### Запуск через скрипты автоматизации

**Windows:**
```cmd
run.bat
run.bat --config test_config.json --stage 1
run.bat --config test_config.json --stage 2
run.bat --config test_config.json --stage 3
```

**Linux / macOS:**
```bash
chmod +x run.sh
./run.sh
./run.sh --config test_config.json --stage 1
./run.sh --config test_config.json --stage 2
./run.sh --config test_config.json --stage 3
```

### Запуск тестов

Прогон полного набора unit-тестов (27 тестов), включая автоматическую проверку стилевых ограничений:

```cmd
run.bat test
```
или
```bash
./run.sh test
```

Прямой запуск через интерпретатор Python:
```bash
python -m unittest discover -s tests -p "test_*.py" -v
```

## 4. Примеры использования

### Этап 1. Вывод параметров конфигурации
```cmd
run.bat --config test_config.json --stage 1
```
Вывод:
```
=== Этап 1. Параметры конфигурации ===
package_name: A
repository_url: test_repos/simple_repo.json
test_mode: True
package_version: 1.0.0
max_depth: 3
filter_substring: 
```

### Этап 2. Сбор прямых зависимостей
```cmd
run.bat --config test_config.json --stage 2
```
Вывод:
```
=== Этап 2. Прямые зависимости пакета A (1.0.0) ===
- B
- C
```

### Этап 3. Построение графа зависимостей (DFS)
```cmd
run.bat --config test_config.json --stage 3
```
Вывод:
```
=== Этап 3. Построение графа зависимостей (DFS) ===
Корень: A (глубина: 3)
Вершины (5): A, B, C, D, E
Ребра (4):
  A -> B
  A -> C
  B -> D
  C -> E
Циклических зависимостей не обнаружено.
```

При работе с циклическим графом (`test_repos/cyclic_repo.json`):
```
=== Этап 3. Построение графа зависимостей (DFS) ===
Корень: A (глубина: 3)
Вершины (4): A, B, C, D
Ребра (4):
  A -> B
  B -> C
  B -> D
  C -> A
Обнаружены циклы (1):
  A -> B -> C -> A
```
